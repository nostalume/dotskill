# Motion Graphics

Own composition timing, motion and rendered-video fidelity. Preserve accepted
content and project choices; the domain owner still owns factual claims. For a
static document or editable slide deck, use document-artifacts. For a bitmap asset,
use an available image-generation capability when appropriate.

Establish the output, editable source needs, dimensions, duration, frame rate,
audio requirements and requested change. Inspect an existing project before
choosing a framework. A style revision does not authorize retiming or rebuilding it.

Before dependent work, satisfy the applicable checkpoints: admitted source and
scope; compatible composition/tools; established visual direction; current-preview
and feedback correspondence; and final export validation. Existing project evidence
can satisfy earlier checkpoints. Choose methods and proceed within authorization;
wait at explicitly reserved user reviews or for missing material decisions.
Silence is not approval. These obligations require no workflow-state files or
repeated intake for a precise edit or render-only request.

Read [operation choices and recipes](references/operations.md) to select authoring,
preview, frame capture and encoding independently. Recommend a compatible
composition based on the brief, visual control, existing source, iteration cost
and delivery constraints. Runtime and platform requirements belong to the chosen
operations. A recipe is a starting point; use its relevant parts directly.

## Compose and revise

- Separate content, layout, visual style, reusable motion and media where those
  parts need independent changes. Use the project's native representation; do not
  introduce a universal timeline format.
- Give motion a purpose: introduce hierarchy, explain a relationship, or direct
  attention. Leave enough reading time; avoid simultaneous competing movement.
- Keep exported state a function of the selected time/frame and admitted inputs.
  Wall-clock timers, live remote data and unseeded randomness can make preview
  differ from export. Follow the selected engine's seeking and readiness contract.
- Preview representative real content when direction is uncertain. Reuse accepted
  direction; ordinary local revisions do not need a new intake or approval cycle.
- Map feedback to the current source and affected time/region. Preserve direct
  project edits. A changed source invalidates affected derived frames and exports.

## Execute and check

Inspect the task root and tools; acquire missing selected dependencies using
[minimal project environments](../system-mutation/references/project-environments.md)
within existing authority, then resume the same request. Honor the user's manager
and use direct official commands, preferring local storage for new task dependencies
while respecting existing project environments. Separate
installation from capture and encoding. Use already admitted executables;
package launchers may download missing
tools, browsers, models or fonts. Keep downloads and preview processes scoped.

Render the exact source that will be delivered. Check start, transitions, holds
and end; inspect text overflow, clipping, fonts and motion continuity. Validate
the encoded output's duration, dimensions, frame rate and audio when requested.
A successful browser screenshot does not prove an encoder result or another
engine's appearance. A technically valid video does not establish aesthetic approval.

For offline work, resolve assets locally and check the chosen operation's actual
network behavior. Browser request blocking is not host-wide network isolation.
Execute trusted project code only within its admitted authority and resource scope.

Return editable sources and requested exports, identify checks and remaining
limitations, and close owned previews/processes. Keep intermediate frames only
when needed for review, reproducibility or recovery. Do not publish or upload
content without the relevant authority.
